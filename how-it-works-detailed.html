🔍 Code Plagiarism Detector

How Does It Work?

A visual walkthrough of Token Winnowing + AST Fingerprinting — the two algorithms powering this plagiarism detector.

🪙

Token Fingerprinting

Converts code into a stream of lexical tokens (ignoring whitespace/comments), then hashes rolling k-grams and picks fingerprints via winnowing. Catches copy-paste well, but sensitive to renaming.

🌳

AST Fingerprinting

Parses code into an Abstract Syntax Tree, then normalises all variable names to NAME and literals to CONST:type before hashing. Robust against renaming & literal changes.

🔄 The Detection Pipeline

1

Source Code → Token Stream

Python's tokenize module strips whitespace, comments, newlines, and encoding markers. Each remaining token is labelled with its type.

Input code:
def count_even(values):
  total = 0
  for value in values: …
Token stream output:
NAME:def NAME:count_even OP:( NAME:values OP:) OP:: NAME:total OP:= NUMBER:0 NAME:for …
2

AST Normalisation (for AST mode)

Instead of lexical tokens, the code is parsed into an AST. All identifiers become NAME, all literals become CONST:type. Only the structure survives.

AST stream for both original.py and renamed.py looks the same:
Module FunctionDef ARG Assign NAME CONST:int For NAME NAME If …
3

Rabin–Karp Rolling k-gram Hashing

A sliding window of k consecutive tokens is hashed using a polynomial rolling hash (Rabin–Karp). This produces one hash per window position in O(n) time.

k=3 example — sliding window over token array:
[T1 T2 T3] T4 T5 → hash₀ 0x3f2a…
 T1 [T2 T3 T4] T5 → hash₁ 0x9b1c…
  T1 T2 [T3 T4 T5] → hash₂ 0x4e7d…
Rolling: each new hash is derived from the previous in O(1) — no re-hashing from scratch.
4

Winnowing — Rightmost Minimum Selection

A second sliding window of size w moves over the hash array. From each window, the rightmost minimum hash is kept as a fingerprint. This guarantees any shared substring of ≥ k+w−1 tokens is detected.

Hash array: [5, 1, 1, 7, 3, 2] · window=3
Window [5, 1, 1] → min=1 at pos 2 → keep (1, pos2)
Window [1, 1, 7] → min=1 at pos 2 → same pos, skip
Window [1, 7, 3] → min=1 at pos 1 → keep (1, pos1)
Window [7, 3, 2] → min=2 at pos 3 → keep (2, pos3)
5

Jaccard Similarity

The fingerprint sets of both files are compared using Jaccard similarity: the ratio of shared hashes to total unique hashes.

Similarity = |A ∩ B| / |A ∪ B|
0.0 = completely different · 1.0 = identical fingerprints

🆚 Token vs AST Mode — When to Use Which?

Scenario 🪙 Token Similarity 🌳 AST Similarity
Direct copy-paste Very High ✓ Very High ✓
Variable / function renaming Medium ~ High ✓
Constant / literal changes Medium ~ High ✓
Added comments / whitespace High ✓ High ✓
Control flow refactor Low ✗ Medium ~
Completely different logic Low ✓ Low ✓

🧪 Sample Programs to Test

Copy any pair below and paste them into your local web app (run python -m plagiarism_detector.web first).

Token: Medium | AST: Very High Same structure, all names changed
Program A — Original 
def count_even(values):
    total = 0
    for value in values:
        if value % 2 == 0:
            total += 1
    return total
Program B — Renamed 
def number_of_evens(items):
    answer = 0
    for item in items:
        if item % 2 == 0:
            answer += 1
    return answer
Expected result: Token similarity will be moderate (operators/structure shared, names differ). AST similarity will be very high (≈1.0) because normalisation makes both look identical.
Token: High | AST: Very High Comments & blank lines added — should not fool either mode
Program A — Clean 
def sum_squares(n):
    result = 0
    for i in range(n):
        result += i * i
    return result
Program B — With Comments 
def sum_squares(n):
    # initialise accumulator
    result = 0
    # loop through each index
    for i in range(n):
        result += i * i  # square it
    return result  # done
Expected result: Both modes should give very high similarity. Comments are stripped by the tokeniser, so they are invisible to both pipelines.
Token: Medium | AST: High Same logic, magic numbers changed
Program A 
def clamp(x):
    if x < 0:
        return 0
    if x > 100:
        return 100
    return x
Program B — Different bounds 
def clamp(x):
    if x < -255:
        return -255
    if x > 255:
        return 255
    return x
Expected result: Token similarity moderate (literal tokens differ). AST similarity high — both constants become CONST:int, making structure identical.
Token: Low | AST: Low Genuinely different programs — should score near 0
Program A — Count evens 
def count_even(values):
    total = 0
    for value in values:
        if value % 2 == 0:
            total += 1
    return total
Program B — Reverse words 
def reverse_words(sentence):
    words = sentence.split()
    return " ".join(reversed(words))
Expected result: Both scores near 0. These programs share no meaningful structure or tokens beyond basic Python keywords.
Token: Low | AST: Medium Same result, different approach (for-loop vs list comprehension)
Program A — Loop style 
def squares(nums):
    result = []
    for n in nums:
        result.append(n * n)
    return result
Program B — Comprehension style 
def squares(nums):
    return [n * n for n in nums]
Expected result: Token similarity will be low (very different token sequences). AST similarity moderate — control structures differ (For body vs ListComp), but surrounding function definition shape is shared.
